# AIRSQAD Cam Linker

Мост между экшн-камерой **GoPro 11** и OSD полётного контроллера на **Betaflight**.

Устройство на базе **ESP32-C3 SuperMini**:
- по **Bluetooth LE** подключается к GoPro, читает её статус и умеет удалённо запускать/останавливать запись;
- по **UART** (протокол **MSP v2**) выводит статус камеры в OSD полётного контроллера, в слоты **Custom Message**;
- поднимает на 30 секунд после включения **Wi-Fi точку доступа** с веб-страницей статуса и настроек.

## Что нужно для сборки

- Плата **ESP32-C3 SuperMini**
- Экшн-камера **GoPro 11** (в т.ч. GoPro 11 Mini)
- Полётный контроллер на **Betaflight** со свободным UART
- Провода для пайки (минимум 3: TX, RX, GND; опционально 5V для питания платы от FC)
- Компьютер с установленным **PlatformIO** (расширение VSCode или CLI) для прошивки

## Схема подключения

```
GoPro 11  <--BLE-->  ESP32-C3 SuperMini  <--UART/MSPv2-->  Полётный контроллер (Betaflight)
                              |
                              v
                    Wi-Fi AP + веб-портал (первые 30 сек)
```

| ESP32-C3 SuperMini | → | UART-порт FC (Betaflight) |
|---|---|---|
| **GPIO4** (RX) | ← | **TX** выбранного UART |
| **GPIO5** (TX) | → | **RX** того же UART |
| **GND** | — | **GND** |
| **5V** (опционально) | ← | **5V** — если хотите питать плату от FC |

- Провода TX/RX подключаются **перекрёстно** (TX↔RX), земля — обязательно.
- Логические уровни 3.3В на обеих сторонах — переходники не нужны.
- Если пины GPIO4/GPIO5 заняты на вашей конкретной плате — поменяйте `MSP_RX_PIN`/`MSP_TX_PIN` в [src/main.cpp](src/main.cpp).

## Сборка и прошивка

Через **PlatformIO**:

```
pio run                              ; сборка
pio run -t upload --upload-port COMx ; прошивка (укажите свой COM-порт)
pio device monitor --port COMx --baud 115200  ; отладочный вывод
```

Конфигурация — [platformio.ini](platformio.ini): `espressif32` / `arduino`, плата `esp32-c3-devkitm-1` (ближайший аналог SuperMini в реестре PlatformIO), зависимость `h2zero/NimBLE-Arduino`.

> `pio device monitor` — интерактивная команда, запускайте её в своём терминале, а не через автоматизацию.

## Настройка Betaflight

1. **Ports** → включите **MSP** на UART, к которому подключён ESP32.
2. **OSD** → включите элементы **Custom message 1, 2, 3, 4** и разместите их на экране (используются все 4 слота).

## Первое включение и веб-портал

При каждом включении платы **первые 30 секунд** поднимается Wi-Fi точка доступа:

- **SSID:** `AIRSQAD Cam Linker`
- **Пароль:** `12345678`
- **Адрес портала:** `http://10.0.0.1`

Подключитесь к этой сети с телефона или ноутбука — благодаря встроенному captive-portal (DNS отвечает адресом платы на любой запрос) большинство устройств **сами** предложат открыть страницу авторизации. Если этого не произошло — откройте `10.0.0.1` в браузере вручную.

Через 30 секунд веб-сервер и DNS портала останавливаются, и плата переходит в обычный режим (поиск/связь с GoPro). Сама Wi-Fi точка доступа при этом физически не выключается (остаётся видна в списке сетей) — полное выключение Wi-Fi виснет на ESP32-C3 при уже запущенном BLE-стеке, поэтому вместо этого просто перестаёт отвечать веб-страница. Чтобы снова открыть портал — перезагрузите плату (питание выкл/вкл).

> Пока активен портал, поиск GoPro по BLE не идёт — Wi-Fi и активное BLE-сканирование делят один радиомодуль ESP32-C3, совместная работа "убивает" отзывчивость точки доступа.

## Веб-интерфейс: разделы

Интерфейс — тёмная тема с логотипом AIR SQAD, все выборы сделаны сегментированными кнопками (не выпадающими списками/радио), интерфейс по умолчанию на английском.

### Статус
4 цветных плитки в ряд:
- **Connection** — зелёная, если GoPro подключена, серая — если нет
- **Recording** — красная во время записи
- **Battery** — цвет плавно меняется от красного (0%) к зелёному (100%)
- **SD card** — зелёная при статусе `OK`, красная в остальных случаях

### Камера
Выбор типа камеры кнопками: **GoPro** / DJI / Insta360 (последние два — заглушки, серые и неактивные, протокол под них не реализован).

Здесь же — чекбокс **"Auto power-on camera on boot"**: если выключить, плата не будет сама искать и подключаться к GoPro при каждом включении (BLE-подключение будит камеру из спящего режима, это не всегда нужно). Ручная привязка кнопкой BOOT продолжает работать независимо от этой настройки.

### Запуск записи
- **AIR** — запись стартует автоматически при **arm** полётного контроллера.
- **SWITCH** — запись включается выбранным **AUX-каналом** (кнопки AUX1–AUX8, порог переключения — верхнее положение свитча).
- **Stop recording on disarm** — принудительно останавливать запись при disarm, независимо от режима выше.

> **Важно:** пока включена **Stop recording on disarm** (включена по умолчанию), режим **SWITCH** работает только при **armed** FC — при disarm запись принудительно остановится/не начнётся, даже если свитч в верхнем положении. Если нужно, чтобы SWITCH управлял записью независимо от arm-статуса — снимите этот чекбокс. Подтверждено на реальном стенде (GoPro 11 Mini).

### Поля OSD (Custom Message 1-4)
Для каждого из 4 слотов OSD можно выбрать, какие данные в нём показывать (полный список — см. [Поля данных в OSD](#поля-данных-в-osd)), сеткой по 2 в строку. По умолчанию: слот 1 — подключение, слот 2 — запись, слот 3 — батарея, слот 4 — статус SD.

### LED indicator
Чекбокс **"LED indicator enabled"** — снимите галочку, чтобы полностью погасить светодиод (например, для скрытности в полёте).

### Language
Переключатель **English / Русский** — меняет язык всего интерфейса портала (кроме текста в самом OSD Betaflight — он всегда на английском, см. [Поля данных в OSD](#поля-данных-в-osd)). По умолчанию — English.

### Привязанные камеры
Список камер, с которыми плата когда-либо была сопряжена по BLE (реальный bond store NimBLE), с кнопкой **"Remove"/"Удалить"** для каждой — снимает привязку, чтобы освободить место под новую камеру.

Все настройки сохраняются в NVS (переживают перезагрузку и отключение питания).

## Привязка (pairing) камеры

**GoPro 11 (с экраном):** Preferences → Connections → Connect Device → GoPro App — камера перейдёт в режим ожидания BLE-подключения.

**GoPro 11 Mini (без экрана):** включите камеру, зажмите кнопку **Mode** примерно на 3 секунды до серии коротких сигналов — камера должна войти в режим Bluetooth-сопряжения. Точная процедура может отличаться — сверьтесь с Quick Start Guide из коробки или приложением GoPro Quik, если не сработает.

Так как у Mini нет экрана, диалога подтверждения не будет — сопряжение (Just Works) должно пройти автоматически, как только плата найдёт камеру в эфире.

После первого успешного сопряжения плата запоминает bond и переподключается автоматически при каждом включении — повторять процедуру не нужно, пока привязка не будет удалена (кнопкой в портале или самой камерой).

## Индикация светодиодом

Используется встроенный светодиод большинства клонов ESP32-C3 SuperMini (GPIO8). Если на вашей плате его нет или он на другом пине — поменяйте `STATUS_LED_PIN` в [src/main.cpp](src/main.cpp).

| Паттерн | Значение |
|---|---|
| Быстро мигает не переставая | Работает Wi-Fi портал (доступен веб-интерфейс) |
| Медленно мигает не переставая | Портал закрыт, идёт поиск/ожидание соединения с GoPro |
| 2 вспышки, пауза, повтор | Связь с камерой установлена |
| 3 быстрые вспышки, пауза, повтор | Камера сейчас пишет видео |
| Не горит | Индикация отключена в настройках |

## Кнопка привязки камеры

Используется встроенная кнопка **BOOT** (GPIO9) — паять ничего не нужно.

**Удержание ~2 секунды** (уже после загрузки платы, не во время включения/сброса!) разрывает текущее соединение с GoPro и форсирует немедленный поиск новой камеры в эфире (15-секундное окно). Чтобы привязать именно новую камеру — старую на это время лучше выключить или убрать подальше, так как выбора из списка найденных устройств нет (нет экрана).

> Если держать BOOT именно в момент включения/сброса питания — чип войдёт в режим прошивки вместо обычного запуска.

## Поля данных в OSD

Доступно для выбора в каждом из 4 слотов:

| Поле | Пример текста | Источник (Open GoPro Status ID) |
|---|---|---|
| Не используется | — | — |
| Статус подключения | `GP OK` / `GP ---` / `PAIRING` | состояние BLE-связи |
| Идёт запись | `REC` / `IDLE` | ID 10 (Encoding Active) |
| Заряд батареи, % | `BAT 87%` | ID 70 (Internal Battery Percentage) |
| Статус SD-карты | `SD OK` / `SD FULL` / `SD REM` / `SD FMT ERR` / `SD BUSY` / `SD SWAP` | ID 33 (Primary Storage) |
| Перегрев | `HOT` / `TEMP OK` | ID 6 (Overheating) |
| Осталось времени записи | `TIME 12:34` | ID 35 (Remaining Video Time) |
| Свободно на SD | `FREE 1024MB` | ID 54 (SD Card Remaining) |
| Ёмкость SD | `CAP 65536MB` | ID 117 (SD Card Capacity) |
| Ошибки SD-карты | `SD ERR 0` (код сырой) | ID 112 (SD Card Errors) |
| Занята (busy/ready) | `BUSY` / `READY` | ID 8 (Busy) |
| Заряд батареи, делений | `BAT BARS 3` | ID 2 (Internal Battery Bars) |

Статус SD-карты (ID 33) расшифрован по официальному enum `PrimaryStorage` из исходников Open GoPro:

| Код | Значение | Текст на OSD |
|---|---|---|
| 0 | OK | `SD OK` |
| 1 | SD Card Full | `SD FULL` |
| 2 | SD Card Removed | `SD REM` |
| 3 | SD Card Format Error | `SD FMT ERR` |
| 4 | SD Card Busy | `SD BUSY` |
| 8 | SD Card Swapped | `SD SWAP` |

Код ошибок SD-карты (ID 112) пока выводится сырым числом (`SD ERR N`) — расшифровка не найдена.

## Устранение неполадок

**В OSD вместо текста видно `CUSTOM_MSG1`/`CUSTOM_MSG2`...** — это плейсхолдер Betaflight для слота, в который ещё не пришли данные. Проверьте: включён ли MSP на нужном UART в Ports, физически ли распаяны TX/RX/GND, совпадает ли скорость (115200).

**В OSD обрезается первая буква текста** — известный и уже исправленный баг протокола (MSP2_SET_TEXT требует байт длины строки перед самим текстом). Если видите это на актуальной прошивке — обновите код из репозитория.

**Wi-Fi портал не открывается / страница не грузится** — убедитесь, что подключаетесь именно в первые 30 секунд после включения. Если браузер долго думает — это может быть связано с блокирующим BLE-сканированием (устранено начиная с версии, где сканирование отложено до закрытия портала).

**`pio run -t upload` пишет "port is busy"** — закройте открытый монитор порта (`pio device monitor`) в своём терминале и повторите.

**GoPro не подключается** — убедитесь, что камера переведена в режим BLE-сопряжения (см. [Привязка камеры](#привязка-pairing-камеры)), и что она в радиусе действия. Проверьте состояние через `pio device monitor` (строка `GoPro: connected=...`) или на странице портала. Если включена настройка «Auto power-on camera on boot» = выключено — плата не станет искать камеру сама, нужна ручная привязка кнопкой BOOT.

**GoPro подключена (`connected=1`), но батарея/SD не обновляются (`-1%`/`0`)** — проверьте, что прошивка актуальная. В более старых сборках это было известным багом: ответы на запрос статуса не доходили без явного апгрейда связи до зашифрованной (`secureConnection()`) и без подписки на все notify-характеристики сразу после подключения (а не только на нужную) — GoPro такое требует по своей же спецификации BLE. Оба момента исправлены в текущей версии.

### Insta360 ONE RS: что выяснили и почему не работает

Камера реально рекламирует BLE-сервис `0xBE80` ("Direct Control", описан в неофициальном реверс-инжиниринге [xaionaro-go/insta360ctl](https://github.com/xaionaro-go/insta360ctl)) с характеристиками `BE81` (write) и `BE82` (notify). Собрали корректный по документации Header16-пакет и отправили `GET_CAPTURE_STATUS`, `CHECK_AUTHORIZATION`, `OPEN_CAMERA_WIFI` — во всех случаях BLE-запись подтверждалась на уровне транспорта (`writeValue() == true`), но камера **не ответила ни разу** ни на одну команду. Похоже, у ONE RS эта часть BLE либо нефункциональна, либо требует недокументированного шага инициализации.

Реальное управление у ONE RS идёт через **Wi-Fi**: сняли `adb bugreport` с телефона во время работы официального приложения Insta360 и нашли в логе живое TCP-соединение `192.168.42.5:34016 → 192.168.42.1:6666` и HTTP-запросы к `192.168.42.1:80/DCIM/...` — это **точно совпадает** с задокументированным Wi-Fi/TCP-протоколом камеры (sync-хендшейк `syNceNdinS`, порт 6666, команда `GET_CAPTURE_STATUS` код 15 и т.д.).

Но: Wi-Fi сеть камеры (`ONE RS 2FCAPE.OSC`, WPA2-PSK) в этом логе работала на частоте **5745 МГц — это диапазон 5 ГГц**. **ESP32-C3 поддерживает Wi-Fi только в диапазоне 2.4 ГГц** — это аппаратное ограничение чипа, программно не обходится. По данным поддержки Insta360 (для похожих моделей X4/ONE X), камера переключается на 2.4 ГГц только автоматически (если 5 ГГц недоступен в регионе или сильно засорён) — ручного переключателя в настройках камеры нет.

**Итог:** для реальной поддержки Insta360 ONE RS по Wi-Fi нужен чип с поддержкой 5 ГГц (в линейке Espressif это, например, **ESP32-C5**) — на ESP32-C3 SuperMini эта камера недостижима ни по BLE (канал не отвечает), ни по Wi-Fi (диапазон не поддерживается железом).

**Решение (2026-09-18):** проект остаётся на **ESP32-C3**. Поддержку Insta360/DJI дальше не развиваем — GoPro остаётся единственной полноценно рабочей камерой, пункты DJI/Insta360 в настройках — задел на будущее (неактивные заглушки в UI). Если позже решите вернуться к Insta360 — потребуется отдельная плата на ESP32-C5 (или аналогичном 5ГГц-чипе) и Wi-Fi/TCP-клиент вместо BLE (см. выше).

```

├── main.cpp               — точка входа, главный цикл, кнопка, LED, формирование OSD-текста

├── bonded_cameras.h        — список привязанных камер поверх NimBLE bond store
└── logo.h                  — SVG-логотип AIR SQAD, отдаётся порталом по /logo.svg
```

## Статус проекта

Рабочий прототип, связка BLE-подключение + опрос статуса + запись + Wi-Fi портал **проверена на реальном стенде** (ESP32-C3 + GoPro 11). Полёт полностью на живом FC пока не тестировался — логика AIR/SWITCH триггера записи и разбор многобайтовых статусов SD-карты (объём/остаток) не проверены за пределами BLE-обмена. Обработка ошибок минимальна, код рассчитан на подстройку под конкретную сборку дрона.
